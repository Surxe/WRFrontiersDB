# External facts the decisions rely on

Facts about third-party products that one or more ADRs depend on. Each entry says how
it was checked and when. Products change; anything here that a design step depends on
should be re-checked when that step is built.

Status values:

- **Verified**: read on the vendor's own documentation on the date given.
- **Reported**: from a third-party source; treat as likely, not certain.
- **Assumed**: believed from general knowledge; not checked for this project. These
  are listed so that nobody mistakes them for verified facts.

## Cloudflare Workers static assets

## Cloudflare R2

| Fact | Status | Source |
|---|---|---|

## DVC

| Fact | Status | Source |

## Proxmox, LXC and Docker

| Fact | Status | Source |
|---|---|---|
| A container's `memory` option is a control-group limit; `swap` adds host swap on top of it. | Verified 2026-10-12 | https://pve.proxmox.com/pve-docs/pct.1.html |
| The `nesting` feature exposes procfs and sysfs so that containers can run inside the container. | Verified 2026-10-12 | same page |
| For maximum isolation Proxmox recommends nesting containers inside a virtual machine rather than inside a container. | Verified 2026-10-12 | same page |
| The `backup` flag on a mount point applies to storage-backed volumes only. How bind mounts are treated by backups was not read (the page was cut off). | Partly verified | same page |
| **Since about November 2025 (containerd.io 1.7.28-2, a fix for CVE-2025-52881), Docker inside an LXC container on Proxmox 9 can fail to start containers** with `open sysctl net.ipv4.ip_unprivileged_port_start file: reopen fd 8: permission denied`. The cause is an interaction between runc and AppArmor. The published workarounds switch off AppArmor confinement for that container. No permanent fix was named. | Reported 2026-10-12 | https://blog.ktz.me/apparmors-awkward-aftermath-atop-proxmox-9 and Proxmox forum threads |
| It does not affect the server's versions (Proxmox 9.2.2, kernel 7.0.2-6-pve, lxc-pve 7.0.0-2, containerd.io 2.4.2, runc 1.5.2): Docker containers start in an unprivileged, nesting-enabled container with AppArmor confinement left on. | Measured 2026-10-21 | spike on the server (ADR-0006, G-0006-1) |

## SQLite

| Fact | Status | Source |
|---|---|---|
| The binary JSON format ("JSONB") and its functions need SQLite 3.45.0 or newer. | Assumed (well known) | https://sqlite.org/jsonb.html |
| The JSON functions are built into SQLite by default from 3.38.0 (before that they were an optional extension), and the `->` / `->>` operators were added in 3.38.0. | Verified 2026-10-20 | https://sqlite.org/json1.html |
| Both machines have SQLite 3.46.1 (through Python 3.13.5). | Measured 2026-10-12 | local |
| The official Python images build Python against the Debian package `libsqlite3-dev`, so Python's `sqlite3` module uses the SQLite of the image's Debian release. | Verified 2026-10-20 | https://github.com/docker-library/python, `3.13/slim-trixie/Dockerfile` |
| Debian's SQLite: 3.40.1 in Debian 12 (bookworm), 3.46.1 in Debian 13 (trixie). So a `-bookworm` image lacks JSONB and a `-trixie` image has it. | Verified 2026-10-20 | https://sources.debian.org/src/sqlite3/ |
| The un-suffixed official Python tags (`3.13-slim`, `3-slim`, `slim`) are Debian 13 (trixie); Debian 12 is only under explicit `-bookworm` tags. | Verified 2026-10-20 | https://github.com/docker-library/official-images, `library/python` |
| `python:3.13-slim` reports SQLite 3.46.1, and `jsonb()` works in it. | Measured 2026-10-20 | `docker run` on the workstation, image digest `sha256:70729b46c69b...` |
| Node 22's built-in `node:sqlite` module bundles its own SQLite, independent of the operating system: 3.51.3 in Node 22.23.2. It is marked experimental. | Measured 2026-10-20 | local, on the workstation |
| A database opened with the URI parameter `immutable=1` is opened read-only, with no file locking and no change detection; if the file changes anyway, results may be wrong. | Verified 2026-10-20 | https://sqlite.org/uri.html |
| The full-text module's default tokenizer does not split Chinese, Japanese or Korean text into words; a trigram tokenizer exists. | Assumed (well known) | https://sqlite.org/fts5.html |
