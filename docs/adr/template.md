## Context

The situation that calls for a decision, and the evidence. For anything measured, give
the date and the method, or cite `docs/research/`. Say which facts were measured, read
from code, stated by someone, verified against documentation, or assumed.

## Decision

Numbered statements of what was decided. Each should be checkable: someone reading the
code later should be able to tell whether it holds.

1. ...

## Alternatives considered

Each real alternative, what it offered, and why it was not chosen. Include options
that were proposed and rejected, with the reason given at the time.

## Consequences

What follows from the decision, including the costs that were accepted.

## Gaps and open questions

What this record leaves undecided, unverified or undesigned. One heading per gap, in
exactly this form, because `tools/docs/build_docs.py` reads it:

### G-NNNN-1. Short title

- **Kind:** decision | verification | design | action
- **Needed by:** the phase or event by which it must be closed

What is open and why it matters.

**Proposed default:** optional. A suggestion, clearly not a decision.

When a gap is closed, append a dated note under it (`**Resolved YYYY-MM-DD:** ...`).
If closing it changes the decision, write a new ADR.
